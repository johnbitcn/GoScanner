# 旧配置兼容

新配置只通过 `device.record_id` 选择默认设备，普通使用见[配置](configuration.md)。本页集中说明仍可读取的旧地址格式，不是新用户的推荐配置。

## 仍支持的旧字段

| 字段 | 旧格式语义 |
| --- | --- |
| `device.host` | 扫描仪数字 IP，不含协议、端口或路径。省略或留空表示未指定设备 |
| `device.protocol` | `wsd` 或 `escl`；省略时按 WSD 解释地址，不表示覆盖设备表的首选协议 |
| `device.scheme` | 默认 HTTP；eSCL 可用 HTTPS，WSD 仅 HTTP |
| `device.port` | 1–65535。旧 WSD 省略时为 `8018`；旧 eSCL 为 HTTP `80` / HTTPS `443` |
| `device.path` | 以 `/` 开头；旧 WSD 省略时为 `/wsd/scan`，旧 eSCL 为 `/eSCL`。保留有效百分号转义，不允许查询参数或片段 |

旧 WSD 示例：

```json
{
  "device": {
    "host": "192.168.1.8",
    "port": 8018,
    "path": "/wsd/scan"
  }
}
```

旧 eSCL 示例：

```json
{
  "device": {
    "host": "192.168.1.8",
    "protocol": "escl",
    "scheme": "https",
    "port": 443,
    "path": "/eSCL"
  }
}
```

这些默认端口和路径是旧解析规则，不是所有型号的服务地址。现在手动添加只输入 IP，程序从发现结果取得实际地址；发现失败不套用这些默认值。证书和网络限制见 [eSCL 与 WSD](escl.md)。

## 迁移与覆盖

- 单纯读取旧配置不改写文件，旧配置可继续使用。
- 用户在 TUI 或普通文本流程明确选用设备、只读验证成功并保存默认选择时，程序将 `device` 替换为记录引用。保留扫描、输出和处理分组。
- 普通 `info` 可以更新设备表，但不自动迁移默认配置。Agent 不分配 ID、不迁移、不写文件。
- 普通设备表写入会补齐缺失的记录 ID；TUI 打开旧列表时也会补齐。纯读取保持不变。
- 旧地址匹配设备表后，默认使用该记录的首选协议。CLI `--protocol` 只影响本次，不将旧配置协议转换成用户首选。
- `record_id` 与任一旧地址字段显式混用会报 `invalid_config`，即使旧字段为空或零也不例外。不要同时保留两套选择方法。
- CLI `--endpoint` 或 `--host` 仍可显式选择目标。旧地址模式保留原来的拆分地址覆盖方式；新引用模式下，仅传 `--port`、`--path`、`--scheme` 会报错，须同时给出 `--host`。

同 IP 或相似型号不是设备身份。不能手工把另一个设备的记录 ID 填入配置来修复身份冲突；应重新发现并明确选择设备。

## 保存失败与回退

迁移顺序是先验证、再写设备表、最后写默认引用。最后一步失败时保留设备记录，旧配置不变，不继续扫描。取消或验证失败不会提交扫描任务。

新增记录字段可能被旧程序的严格 JSON 校验拒绝。升级前备份 `config.json` 和 `drives.json`；回退时恢复与旧程序匹配的成对备份，不能只替换二进制。不要在程序登记设备的同时手工编辑配置。
