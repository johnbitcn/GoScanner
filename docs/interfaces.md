# 人类界面与 Agent 输出

## 选择模式

| 调用环境 | 行为 |
| --- | --- |
| `goscanner`，标准输入和输出均为终端 | 打开内联扫描 TUI |
| `goscanner scan/info/discover`，标准输入和输出均为终端 | 打开对应任务的内联 TUI |
| 标准输入或输出不是终端，或 `TERM=dumb` | 保留原有无颜色输出；无子命令时显示帮助 |
| `goscanner --agent <子命令>` | 无交互执行，结束时输出一个 JSON 对象 |

`--agent` 必须在子命令前。不会因为输出进入管道而隐式启用 Agent 协议。

## 语言契约

**人类界面支持本地化；面向 Agent 时，项目生成的全部信息必须使用英文。用户、设备及系统／依赖库提供的原始内容不强制翻译。**

人类界面已支持英文和简体中文；Agent 英文边界独立于人类语言设置。实现方式、实施前盘点和验证范围见文末“i18n 输出盘点与验收”。

### 按接收方和来源划分

| 内容 | 语言规则 |
| --- | --- |
| 人类 TUI、普通 CLI 帮助、状态、提示和错误解释 | 支持英文 `en` 和简体中文 `zh-CN` |
| Agent JSON 的字段名、项目定义的枚举值、状态和错误码 | 固定英文，不参与 i18n |
| Agent 的 `error.message`、顶层 `warnings`、`processing[].warnings`、`help` 中由项目生成的说明 | 必须使用英文，不受人类界面语言或系统 locale 影响 |
| Agent 模式的项目 stderr 诊断，包括 stdout 写入失败及 npm 启动失败提示 | 必须使用英文；正常业务错误仍只写入 JSON |
| 用户输入、文件路径、设备名称、型号、设备状态及协议原始值 | 不作语言翻译；保留既有校验和规范化，不因包含非英文字符而拒绝 |
| 设备原始诊断、系统及依赖库的原始错误 | 不强制翻译；若保留，必须与项目的英文解释可区分，不能作为项目发出的操作指令 |

英文约束针对信息来源，不是字符集约束。项目的英文说明可以引用中文路径或设备名称；被引用的外部数据不是项目文案。不能检查整个 JSON 是否只含 ASCII 字符来判断合规。

非 TUI 的 `discover`、`info` JSON 同样不进入人类界面的翻译流程：字段名和项目定义的协议值保持英文，设备数据保持其原有语言。它们在非 Agent 模式下的 stderr 提示属于人类展示路径。

### 机器语义与展示边界

- Agent 根据 `status`、`error.code` 和结构化结果字段判断结果，不解析说明文字。英文措辞本身不作为稳定接口。
- 同一概念使用同一英文术语。事实、建议和操作条件分开表达；不能把“失败”自动解释为“可以安全重试”。
- 扫描任务是否已提交、文件是否已保存、能否重试等事实不能因语言改变。保留现有退出码、不覆盖文件、不自动重试和清理约定。
- 业务逻辑及扫描事件表达结果与事实；人类展示路径生成本地化文案，Agent 路径生成固定英文文案。不解析人类日志来生成 JSON，也不通过替换已拼接错误中的中文来实现翻译。
- 项目内部生成的中文错误不是“外部原始错误”。必须沿调用链处理其项目说明，不能仅添加英文前缀后原样透传。外部原始错误在英文解释中以 `External error: "..."` 引用；设备 WSD Fault 原文以 `Device diagnostic: "..."` 引用。引用中的转义字符用于保留原始内容，不将其解释为项目指令。不新增 JSON 字段。
- 帮助语言分离后，仍保留 Agent 的 80 列纯文本约定，以及不访问设备、不改变终端模式的约定。人类帮助只提取配置中的语言字段；Agent 帮助不读取配置。

### 人类界面语言选择

`--lang` 和配置文件的顶层 `language` 都接受 `auto`、`en`、`zh-CN`。省略配置字段时默认 `auto`。参数可以放在子命令前，或作为子命令参数；查看帮助时放在 `--help` 前。重复指定时，最后一个已解析的 `--lang` 生效。

```bash
goscanner --lang zh-CN
goscanner --lang en scan --help
goscanner scan --lang zh-CN -o 合同.pdf
goscanner --agent --lang zh-CN info  # JSON 的项目说明仍为英文
```

选择顺序：**显式 `--lang` > `~/.config/goscanner/config.json` 的 `language` > 系统语言自动检测**。例如，配置 `"language": "zh-CN"` 可固定中文，`--lang en` 可临时覆盖为英文。显式 `--lang auto` 跳过配置中的固定语言，直接自动检测。

自动检测按 `LC_ALL` > `LC_MESSAGES` > `LANG` 使用第一个非空值；该值不受支持或全部缺少时回退英文，不继续尝试低优先级变量。

- 简体中文环境包括 `zh`、`zh_CN`、`zh_SG`、`zh_Hans` 及 `zh_Hans_*`；接受 `_` / `-` 分隔，忽略大小写、字符集和 modifier 后缀。
- `C`、`POSIX`、缺少 locale、繁体中文及其他未支持的语言均回退英文。不读取 `LANGUAGE`。
- 非法或缺少 `--lang` 值返回参数错误；不访问设备。`--agent` 如使用，仍须放在所有其他参数之前。
- `--lang` 只影响本次人类展示，不自动写回语言偏好。持久化偏好可编辑配置的 `language`，或在 TUI 设置页选择并确认保存。没有显式语言参数时，保存后立即切换界面；存在参数时，该参数继续控制本次界面，新偏好在后续未指定参数的运行中生效。保存默认设备时保留该字段。
- 人类帮助只提取语言字段，不应用或校验扫描设置，不访问设备、不写配置。配置无法读取、JSON 损坏或语言无效时，帮助按系统语言回退；正常命令仍严格校验配置，无效语言返回 `invalid_config`。
- 自动选择可能显示英文。需要保持中文时，设置配置 `"language": "zh-CN"` 或显式使用 `--lang zh-CN`。
- Agent 接受合法的 `--lang`，但其 JSON、帮助及异常 stderr 的项目说明始终使用英文；非法语言参数也按英文 Agent 错误协议报告。

### 当前实现

- `i18n.go` 选择语言并在请求和 TUI model 中显式传递，不使用可变的全局当前语言。`i18n_catalog.go` 使用编译进程序的模板对照表，不引入翻译依赖或外部资源文件。先选择模板，再插入路径、名称和其他数据；不能把外部数据当作翻译键。
- `diagnostic.go` 在诊断生成处分别保存英文和原有人类文案。`Error()` 与 `Unwrap()` 保留原始错误文本和错误链，人类展示按所选语言读取诊断，JSON 序列化始终使用英文。嵌套诊断和 `errors.Join` 分别处理，不解析最终中文字符串。
- `commandError` 保留内部原因，JSON 的 `message` 使用英文表示；字段名、错误码和退出码不变。顶层及逐页处理警告仍序列化为字符串数组，没有增加协议层级。
- 警告事件携带诊断，而非已拼接的人类展示文字。TUI 和兼容文本按所选语言展示，Agent JSON 使用英文。设置项只翻译显示标签，不翻译 `color`、`gray`、协议名等实际参数值。
- `agent_help.go` 提供独立英文帮助内容，与两种人类语言共用排版器。默认值的着色偏移按翻译后的正文计算。Agent 帮助固定为 80 列无样式文本，不读取配置、不访问设备。
- stdout 写入失败及 npm 启动失败的项目诊断，在人类模式下使用所选语言，在 Agent 模式下固定使用英文；外部原始错误保留为引用数据。npm 在二进制尚未启动时自行选择诊断语言，不改变传给二进制的参数、环境变量或信号。

## 命令帮助

`goscanner --help` 只显示用法、命令导航、常用示例、全局选项和配置位置。具体参数使用 `goscanner scan --help`、`goscanner info --help` 或 `goscanner discover --help` 查看。

- 子命令参数按设备、扫描、输出、连续扫描、图像处理、超时和兼容参数等用途分组，只列该命令接受的参数。
- 宽度为 72 列及以上时，参数与说明分栏；说明续行对齐说明列。较窄时，参数独占一行，说明缩进 4 格。
- 按中文、英文和 Unicode 显示宽度主动断行，正文最多 88 列。重定向输出固定使用 80 列纯文本，不添加终端控制序列。
- 支持颜色的终端使用青色标题、粗体参数和灰色默认值。`NO_COLOR` 非空或 `TERM=dumb` 时使用纯文本，即使设置了强制颜色也不启用颜色。
- 帮助只按标准输出判断终端能力，不要求标准输入为终端。不清屏、不启动交互界面、不改变终端输入模式、不启用分页器。
- 人类帮助仅读取语言设置，不发现或查询设备，即使配置损坏也能显示。Agent 帮助不读取配置。`--agent <命令> --help` 仍返回一个 JSON 对象，`help` 字段固定为 80 列无样式文字，不随终端变化。

## 人类 TUI

使用 Bubble Tea v2 处理交互，Lip Gloss v2 排版，Bubbles v2 提供输入框和结果滚动区域。界面采用内联模式，不使用全屏备用缓冲区，不启用鼠标，不显示虚构的百分比。

配色采用终端基础调色板：青色突出标题和选中项，绿色表示就绪／成功，黄色表示等待／警告／部分完成，红色表示失败，蓝色表示文件路径，灰色用于辅助说明和关闭项。颜色之外仍保留 `>` 选择标记、状态文字和警告标签。

设置 `NO_COLOR=1` 可关闭 TUI 颜色；仍保留必要的交互控制序列。终端渲染器会根据颜色能力调整输出。Agent JSON、非 TUI 文本和界面异常退出时的文字报告不添加颜色。

### 扫描就绪

人类 TUI 默认开启手动连续扫描，仍须按 Enter 才开始第一页。可在设置列表中关闭“连续扫描”，或在启动时使用 `goscanner scan --manual=false`。非 TUI 文本模式仍默认单页扫描，Agent 模式仍不支持 `--manual`。

此默认值不修改配置或输出格式。使用默认 JPEG 时，连续扫描按 `scan-时间戳-001.jpg` 等名称逐页保存；选择 PDF 才会在结束时合并。

进入扫描页时，先按扫描超时设置执行只读能力查询。只有设备报告 `Idle`，且支持当前 DPI、颜色、区域及实际扫描源格式时，才显示“就绪”并启用 Enter。PDF 校验 JPEG 源格式；WSD 的 PNG 校验 TIFF 源格式，eSCL 的 PNG 与实际扫描共用 PNG、TIFF、JPEG 源格式协商。检查不创建扫描任务、不生成输出文件、不加载 AI 模型。

忙碌、停止、连接／协议错误、超时或参数不受支持时，显示“无法确认就绪”及原因，不接受 Enter 开始扫描。可重新检查、修改设置、更换设备或退出。

- Enter：仅检查通过后，按界面所示参数开始扫描。
- `r`：重新检查设备状态和当前参数。
- `d`：打开更换设备界面，手动添加或开启自动发现。
- `s`：编辑本次扫描参数。
- `q` 或 Esc：退出，不启动扫描。

首页设备栏显示“**型号** + 蓝色 IP + 橘黄色当前协议”，与已保存设备列表一致。已有默认设备时，仍须执行预检查，不能把“已配置”当作“就绪”。新设备确认时先执行只读服务验证，并复用同一份能力结果判断就绪；应用或放弃设置编辑返回扫描页时，会重新查询。

界面显示最近检查时间。这是当时状态的快照，不是设备预约；不做后台轮询。按 Enter 后，扫描流程仍会重新读取能力并校验，防止检查后设备状态发生变化。

### 更换设备

缺少默认设备时，先打开此界面，不主动搜索网络。已有设备时按 `d` 进入。

先列出已保存设备，每行显示“**型号** + 蓝色 IP + 橘黄色首选协议”。选中设备按 `p` 可切换并保存首选协议，只允许选择已确认支持的协议；重新发现不覆盖用户偏好。列表包括发现记录和验证记录，但选择后仍须执行一次只读验证，成功后才修改默认设备。列表下方依次提供“手动添加”和自动发现开关。

选择“手动添加”后只显示 IP 输入框、“发现并使用设备”和自动发现开关。不需要用户填写端口、路径、协议或 HTTP/HTTPS。程序从发现结果取得实际地址，按设备表首选协议验证；新确认的双协议设备默认 eSCL。发现失败不猜地址，连接失败不换协议。

- ↑/↓ 或 Tab / Shift+Tab：选择字段、按钮或发现结果。
- 在 IP 字段中直接输入或粘贴，Enter 移到确认按钮。
- 选中“发现并使用设备”按 Enter：按 IP 筛选发现结果，取得服务地址，再只读验证；只得到一条设备记录时自动进入验证，多条无法确认同一身份时要求选择设备。发现期间不能编辑 IP，Esc 可以取消。
- 查询成功后先登记设备表，再将稳定 ID 写入 `config.json` 的 `device.record_id`；地址无效、身份明确冲突、超时或保存失败时，不替换原默认选择、不启动扫描。
- Esc：手动表单返回已保存设备列表；设备列表有原设备时返回并重新检查原设备，没有原设备时退出。Ctrl+C 可取消验证。

服务验证通过不等于当前可扫描。有效设备即使忙碌也可以保存，但只有报告 Idle 且支持当前参数时，扫描页才允许开始。`info` 直接显示此次验证所得的能力；`scan` 复用同一份结果判断就绪，不紧接着重复查询。真正开始扫描时仍会重新校验。

#### 自动发现开关

默认关闭。选中开关按 Space 或 Enter 后，执行一次局域网发现；不是持续轮询。发现阶段可继续编辑手动地址。

- 关闭开关：取消当前发现并清空本次搜索结果；忽略此前任务迟到的结果。不会删除已保存记录。
- 搜索开启时，在按钮或结果区域按 `r` 可重新搜索。单次发现的超时为当前命令超时与 10 秒中的较小值。
- 主动开启自动发现开关时，即使仅发现一台也不会自动采用。选中结果按 Enter 后使用其实际服务地址，按首选协议验证，成功才保存。
- 开始验证手动或选中设备时会停止发现。验证失败仍可修改地址、重试或重新开启发现。

独立的 `goscanner discover` 仍按显式命令执行发现，不选择或修改默认设备；普通模式会记录发现信息，Agent 模式不写设备信息表。

#### 设备信息表

`~/.config/goscanner/drives.json` 在首次记录时创建。人类 TUI、普通 `discover` 和普通 `info` 更新此表；Agent 模式仍不写配置或设备信息表。

- `record_id` 是稳定的本地记录主键；`record_aliases` 保存可靠合并前的本地 ID。主 ID 和别名解析到同一条记录，不是设备硬件身份。
- 仅在可靠身份信息确认一致时跨协议合并，不能仅凭同 IP 或相似型号合并。发现保存型号、地址及各协议身份；`preferred_protocol` 保存用户设置，`protocol` / `endpoint` 指向选用的入口。
- 成功的只读查询保存 `verified` 与能力、状态快照 `info`，不会清空已有型号。
- `discovered` 与 `verified` 表示历史记录，不代表当前就绪。每次选用仍重新查询。
- `GetScannerElements` 不提供型号。只有手动验证、没有发现元数据的设备显示“未知型号”；后续发现会补充真实型号，不使用名称或虚构型号替代。
- 使用 `0600` 权限、写入锁和原子替换。损坏的 JSON、未知字段、重复地址或符号链接会报错，不自动覆盖。

### 参数编辑

设置以完整列表显示：分辨率、颜色、扫描区域、输出格式、输出路径、连续扫描、PDF 每页独立保存、AI 纠偏、AI 裁切、界面语言，以及“保存并应用”。小窗口中列表随选中项滚动。

- ↑/↓：选择设置项。
- Enter：展开该项的选择列表，或编辑输出路径。
- 选择列表中 ↑/↓ 选择值，Enter 确认，Esc 返回设置列表。
- Space：直接切换开关项。
- 选中“保存并应用”并按 Enter：校验全部设置，保存配置，返回扫描页并重新检查设备；不会自动开始扫描。保存失败时留在设置页，保留草稿和原设置，不改变当前语言。
- 设置列表中 Esc：放弃全部修改；文字输入中 Esc：仅放弃当前输入。

| 设置项 | 输入方式 |
| --- | --- |
| 分辨率 | 从设备水平、垂直 DPI 的共同值中选择 |
| 颜色 | 选择设备支持的彩色或灰度；不提供未开放的黑白模式 |
| 扫描区域 | 选择 A4、完整平板或自定义区域；仅自定义区域需输入毫米坐标 |
| 输出格式 | 设备支持 JPEG 时提供 JPEG、PDF；支持原生 TIFF 时提供 TIFF、PNG；eSCL 支持 PNG 或 JPEG 源时也提供 PNG |
| 输出路径 | 编辑文件路径，支持粘贴；Enter 确认，Esc 放弃当前输入 |
| 连续扫描、PDF 每页独立保存、AI 纠偏、AI 裁切 | 选择开启／关闭，也可直接按 Space 切换 |
| 界面语言 | 选择自动检测系统语言、`English` 或 `简体中文`；语言名称固定使用本体语言，不随界面语言翻译。选择值仍是草稿，整体确认后才保存 |

选择输出格式时自动更新文件扩展名，不创建文件。切换为非 PDF 格式会关闭“PDF 每页独立保存”，并给出提示。没有有效设备能力数据时，不猜测 DPI、颜色或输出格式，应先返回扫描页重新检查。

确认时保存全部可见值：语言、DPI、颜色、区域、输出目录／格式、连续扫描、PDF 每页独立保存和两项 AI 开关。输出文件名不持久化，后续自动生成，避免重复使用同一文件名；保存配置不创建或覆盖扫描文件。设备和超时等非菜单设置保持不变，保存前重新读取配置以保留这些字段的外部改动。配置写入复用默认设备保存的同目录临时文件、同步、原子替换及符号链接拒绝检查。

设备声明不保证所有参数组合都可用。保存后仍执行就绪预检查，真正扫描前也会重新校验。连续扫描偏好会影响后续普通文本模式；Agent 仍禁止交互，可显式用 `--manual=false` 覆盖已保存的开启状态。

### 扫描与结束

- 扫描中 Ctrl+C：取消本客户端任务，等待清理；合并 PDF 会尝试保存已完成页面。
- 连续扫描等待时 Enter：扫描下一页。
- 连续扫描等待时 Esc：正常结束并保存。
- 结果界面 ↑/↓ 或 PgUp/PgDown：滚动。
- 结果界面 Enter、Esc 或 `q`：退出。

取消返回 130。任务清理最多额外等待 10 秒；文件保存和 PDF 合并不是硬实时可中断操作。强制结束或断电仍可能留下暂存图像。

## Agent 模式

```bash
goscanner --agent discover
goscanner --agent info --host 192.168.1.8
goscanner --agent scan --host 192.168.1.8 -o document.pdf
```

规则：

1. 必须指定子命令。不显示菜单、不等待按键、不输出进度或装饰内容。
2. 使用明确指定的设备或配置中的默认设备，匹配设备表后按首选协议连接。只给未登记 IP 时允许按 IP 筛选发现；未提供任何地址时返回 `device_required`，不自动发现或选择设备。CLI `--protocol` 仅覆盖本次，不写入偏好。
3. 不支持 `--manual`。逐次执行 `scan` 可生成独立文件；不保留跨命令的连续扫描会话。
4. 不修改配置，不覆盖已有文件，不自动重试扫描。
5. 正常执行期间 stdout 为空；结束时输出一行紧凑 JSON，包含换行结尾。
6. 正常业务错误也放在 JSON 中，不重复写入 stderr。若 stdout 自身写入失败，只能向 stderr 报告，并返回非零退出码。
7. `--agent --help` 和 `--agent <子命令> -h` 也返回 JSON，帮助正文放在 `help` 字段中。

### 结果字段

字段名和错误码用于程序判断。不要依靠说明文字的措辞或字段顺序判断结果。无关字段省略。

| 字段 | 含义 |
| --- | --- |
| `status` | `ok`、`error` 或 `partial` |
| `files` | 成功发布的输出文件绝对路径 |
| `pages` | 成功发布到 `files` 中的总页数；零页时省略 |
| `originals` | AI 处理所保留的设备原图路径 |
| `retained` | 已知保留的暂存文件或目录路径；其他保留说明可能出现在错误正文中 |
| `warnings` | 影响发现或处理结果的警告 |
| `devices` | `discover` 结果数组；没有设备时为 `[]`。记录首选 `protocol` / `endpoint`，唯一匹配已有记录时可含 `record_id`，新发现记录可省略该字段；已确认双协议时包含各自的 `endpoints`；字段与身份规则见 [eSCL 与 WSD](escl.md) |
| `info` | `info` 返回的设备能力 |
| `processing` | 启用 AI 时的逐页处理信息：`page`、`changed`、`detected`、`angle_reliable`、`angle`；角度单位为度，不可靠时不要使用 |
| `error` | 含稳定 `code` 与可读 `message` 的对象 |
| `help` | 仅帮助请求返回 |

成功：

```json
{"status":"ok","files":["/absolute/path/document.pdf"],"pages":1}
```

缺少设备：

```json
{"status":"error","error":{"code":"device_required","message":"No scanner was specified and no default scanner is configured. Run goscanner --agent discover, then specify --host or --endpoint."}}
```

取消或失败时，若已有输出文件、原图或已知暂存文件，则 `status` 为 `partial`，但仍返回非零退出码。`partial` 不保证主输出已生成，应检查 `files`、`originals`、`retained` 和错误正文。

### 错误码与退出码

| 错误码 | 含义 |
| --- | --- |
| `invalid_arguments` | 命令或参数不合法 |
| `invalid_config` | 配置无法读取、解析或应用 |
| `unsupported_interaction` | Agent 模式使用了 `--manual` |
| `device_required` | 没有明确设备或默认设备 |
| `discovery_failed` | 设备发现失败 |
| `device_resolution_failed` | 无法从设备表或发现结果取得唯一的目标服务地址，包括身份歧义或未确认支持所指定的协议 |
| `device_record_not_found` | 默认记录引用或别名已失效，须主动重新选择设备 |
| `device_identity_conflict` | 查询结果与已存的可比较身份明确冲突，未登记默认选择或提交扫描任务 |
| `info_failed` | 设备能力查询失败 |
| `scan_failed` | 扫描、处理、文件保存或清理失败 |
| `timeout` | 发现、能力查询或单页扫描超时 |
| `cancelled` | 调用被取消或收到中断信号 |

退出码：成功为 0；执行失败或部分完成为 1；参数或配置错误通常为 2；取消为 130。为兼容原行为，不支持的输出扩展名仍返回 1。

创建扫描任务时断线，不能据此推断设备没有执行任务。先检查扫描仪状态，不要直接重试。

## 非 TUI 的兼容文本模式

未指定 `--agent` 且不符合 TUI 条件时：

- `discover`：保留原有 JSON 数组。
- `info`：保留原有能力 JSON 对象。
- `scan`：按所选语言显示状态和文件说明；路径、页数及退出行为不变。
- 设备选择仍读取交互终端；没有控制终端时必须指定设备。
- `--manual` 仍使用原有终端输入：按任意键继续，单独 Esc 结束。

这些输出用于兼容既有调用，不是 Agent 结果协议。需要稳定结构的脚本应显式使用 `--agent`。

## 验证范围

自动测试使用模拟 WSD / eSCL 服务、公开能力响应样本和 Bonjour callback stub，不代替真实设备扫描验收。覆盖 JSON 成功与错误、默认设备只读使用、禁止交互、拒绝覆盖、PDF 部分保存、TUI 状态与参数编辑，以及 macOS 伪终端中的扫描、换页、取消和终端模式恢复。就绪检查覆盖 Idle、忙碌、停止、HTTP／协议错误、超时、参数或源格式不支持、取消和显式重查；伪终端还覆盖配置中的默认设备先忙碌、重查恢复后才允许扫描的流程。

伪终端测试不是实机扫描验证。真实扫描仪、不同终端模拟器和 Linux TUI 尚须单独验证。
